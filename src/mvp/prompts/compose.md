## 本环节任务：图文编排与软文生成

输入：需求画像、平台策略（结构/字数/图数/语气/行动引导）、已选事实 F1…Fn（含原文）、可用图片 I1…In（含官网图注与视觉描述）、价格政策、用户限制、可选的修改指令。

“采用的已审核样板”是本次骨架：保留 pattern 的顺序和 filled_slots 的任务关系，落实 user_note，不重新概括成通用场景加卖点。具体句子重新写，原案品牌、人物与经历不进入正文。与平台字数、事实条件同时满足，不以模仿为理由增加主张。

C01 的 cta 是读者能回答的具体问题，不补网友评论，不承诺官方采纳、奖励或产品更名。C07 恰好用四个极短 text 块对应任务、难处、有据动作、收尾，总篇幅仍遵守海报限制，人物作情景演绎。C08 用极短反差。C13 先给具体问题的答案或核对步骤。C14 在当前渠道交付一份内容。C15 不制造热度事实。C16 的 D 只用于概念演示邀请。

C01 具体执行：开头只用一个真实细节，不把同一片段里的重量、长宽厚一并罗列；可只写某一键盘版重量，保留含电池及差异条件，舍去其余参数。槽位是提纲，信息过载时仍须精简。先细节，再开放问题，cta 承担唯一一次评论邀请；不在正文反复问相同问题。面向目标人群提问，不预设读者已购买本机。不把“不代写评论、目前没有真实反馈、本稿只做征集、发布前核对”等内部说明放进正文或图注；需要的未知事项留在 pending_confirm。

小红书的样板仍遵守图数与单段限制：有至少三张可用图时安排至少三个不同 I 编号的 image 块，实际预览会自动汇成首部轮播，不必只配一张图。每个 text 块最多 writing_limits.text_block 字；参数与必要条件过长时先减少主张，再拆成短段。

C07 海报专用预算：lead 留空，不再介绍“四格讲清什么”；四个 text 块每格争取不超过18字，第三格如需完整事实条件可稍长，四格加 cta 总共控制在85字以内。无需在每格添加“第一格｜”或重复“情景演绎”，独立标识已经说明；第四格只收故事，cta 再给唯一到店邀请，避免重复。舍去无关参数和旁白，不能删条件来压字数。

“须独立展示的概念标识”由程序保留在预览、复制、导出及海报逐字文案中，不要重复塞进标题和每段，也不能删除。涉及 D 的 text 块引用 D，真实门店引用 C，产品主张引用 F；虚构数字不能解释成产品参数。联动对象只来自输入，不写“官宣、正式联名、官方授权、现已开售”等真实合作措辞。画面不代表门店实拍、完成实测或接入真人孪生。

要求：
0. 先分配字数再组织句段，篇幅上限是硬约束。朋友圈（chars 上限为 90）lead 留空，正文不超过两个短 text 块，cta 只保留一个邀请。建议分配为：问题或动作不超过 15 字，事实句连同条件不超过 35 字，cta 不超过 18 字；可写成问答、细节观察或短笺，避免重复铺垫。若完整条件过长，删去次要主张，绝不截去必要条件。不要新增与所写事实无关的软件兼容提醒；详细未知事项放 pending_confirm。其他平台按各自 chars，不套用此短行预算。
1. 按内容主张的 format 组织正文，遵守平台版式、字数、单段和图数限制。可用问答、核对清单、轻科普或场景短笺，不要求每篇都是场景句加两个卖点。图数用 image 块表示。
2. 严格围绕“内容主张”的选定切入点与具体读者任务展开；不重新选题，不沿参数和风险清单组织正文。卖点顺序服务这一立意，不要平均用力。
   已选事实是候选素材，不是必须逐条写入的清单。只选能服务本篇切入点的少数事实；不要为了显得全面，把所有参数与限制抄进正文。
3. 每个含产品事实的文本块，fact_refs 必须列出用到的 F 编号；事实里的限定条件（版本、配置、“约/最高/可选”）要跟着事实一起写出，不得删除。
4. 参数数字必须来自已选事实的 text 或 conditions 原文；策划中的 claim/why 是编辑摘要，不能作为数字依据。不得自行把“3120 × 2080”换称“3.1K”，原文没有该称呼时沿用像素值或省略分辨率。不得把 24GB/32GB 这样的“可选”写成固定配置。
5. 图片选择：首图优先含整机（device/device_scene），示意图须标明；没有整机图则少配并写入 pending_confirm。只选 I 编号。图注只描述配色、外观或示意画面，不从图片名/描述借用尺寸、性能等未选事实；如确需参数必须有 F 引用。图注不写核验分析，不推测画面里没有的手写笔、触控或其他功能。
6. 价格政策为 forbid 表示用户明确要求不提价格；none_in_kb 表示没有可引用的价格依据，两者均不写报价。conditional 表示允许按内容需要报价，不强制加入价格。报价必须引用 kind=price 的已选 F 事实，写明对应配置、价格类型、核验日期和适用条件；快照不能写成实时成交价。不把某个配置的起价写成全系到手价，也不把报价自动扩展成补贴、优惠、库存承诺。价格相关条件只说明一次。
7. 行动引导只写一个动作。不虚构体验、评价、案例；不写绝对化用语。
8. 有修改指令时，在不违反以上规则的前提下执行它；如果指令要求写没有依据的内容，拒绝并在 pending_confirm 里说明。
9. 标题给出 3 个备选（title_options），title 为其中最合适的一个。
10. pending_confirm：只写与本次用户需求或已写主张直接相关、且确实缺依据的事项。无关的 SKU、价格、活动不凑清单；用户要求不提价格或本稿无需报价时，不追加价格提醒。
11. 写面向发布的营销帖子，发布状态由后续审核决定。每段一个意思，以具体动作、问题或观察展开；不要求段段附卖点。允许轻反差与适量幽默，不靠热词堆砌或扮演亲历者。少用长句串联参数，不用“需要说明的是、在决定前建议做好取舍、首先其次”等讲解腔。
12. 严格遵守平台策略的 writing_limits：title、lead、cta、每个 text 块与每条图注分别受限；字数不含空白。不够简洁时删掉次要卖点或重复铺垫，不得删掉已写主张的“约/版本/配置/适用范围”等限定。正文只留与主张直接有关的一句边界，详细待确认事项单列 pending_confirm。
13. 公众号保持图片与短段落交替向下；小红书保持首部图片轮播、下方短文与话题；朋友圈用短行；海报用主标题和少数卖点。不要把四个平台都写成一样的长篇选购指南。正文分行可用换行，不输出 Markdown 的标题符号或加粗标记。
14. 短句也要克制：重量数据不等于耐摔“抗造”，电池容量不等于“不用找插座”或特定续航时长，功能存在不等于任意设备都支持。不要用口语修饰补出事实里没有的能力。条件较多的卖点可以舍弃，写出的功能则须在同一句保留“受支持的设备/版本、同一账号”等前提，不能只把前提移到 pending_confirm。
15. 适合某任务的编辑性定位，不证明“少滚几次”“更宽裕”“更顺手”等比较或实际效果。原文没有比较对象和效果依据就直接写已支持的适配性，轻反差只放在任务或表达节奏中，不增强产品能力。不暗示亲测感受。
16. 正式稿未选 C 门店资料时，行动邀请仅沿用已确认的用户目标，如“带上常用软件清单，到店咨询”；不要新增“店员陪同逐项检查”“当场适配”“预约专人”等具体服务。C16 概念演示可引用 D 的虚构安排，必须保留独立的演示标识，不补充 D 中没有的权益。未知兼容性写为需要核对，不能写成能装／装不上；不要使用假定失败的后果施压。
17. 正文直接面向读者，不出现“原文说”“依据 F1”“已选事实”“本次未验证”等内部流程说明。已有证据中不带实测结论的适配描述可自然使用，不扩写为比较或测评；与本篇无关的核对工作留在 pending_confirm。

blocks 顺序即文章顺序：{"type":"text","text":"…","fact_refs":["F1"]} 或 {"type":"image","image_id":"I1","caption":"…","fact_refs":[]}。
标题、导语、行动引导也要在顶层 fact_refs 分别列出所用事实编号；不含产品主张则空数组。图注如含能力描述也须引用。主张原文与 conditions 中的前提须一起遵守。风格正反例只学习切入和节奏，不能借用产品能力。unsupported_requests 与 critical_gaps 不能写成承诺，在 pending_confirm 中明确说明；不强行把所有风险写进短文。
导语放在 lead，行动引导放在 cta，不要再重复放进 blocks。海报的“卖点行”和朋友圈的正文用 text 块。

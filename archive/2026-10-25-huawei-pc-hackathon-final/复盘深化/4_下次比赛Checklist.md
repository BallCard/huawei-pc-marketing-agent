# 下次比赛 Checklist

- 来源：2026-10-26 赛后复盘（1_、2_、3_ 的浓缩可执行版）。
- 用法：比赛第一天贴出来，每周过一遍；不满足就停下来重排工作。

## 0. 读题（第一天必做）

- [ ] 读官方手册原文，**抄出评分表分值与权重**（而不是只看功能要求）。
- [ ] 抄出统一测试任务/现场检查项，把它们当作自己的测试用例写进 README。
- [ ] 列出并体验同赛道强队入口（GitHub / 魔搭 / 应用），记录各自的一句话主张和一个硬数字。
- [ ] 写一句话"破题"：我们答的是哪几栏的分（≥50 分的内容侧优先）。

## 1. 对照证据（最迟第二周做出）

- [ ] 同一产品 × 3 人群 × 2 平台，各生成一篇，**并排保存**开头/结构/图数/CTA 差异。
- [ ] 同题盲评：通用模型 vs 我们，请目标用户盲打自然度/贴合度/可发布率/修改量。
- [ ] 留一个"失败案例"：同一输入，我们拦住了什么、通用模型编了什么。
- [ ] 每条证据记录：任务输入、模型/资料/代码版本、完整成稿、真实耗时。

## 2. 主张与证据（展示只留一个画面）

- [ ] 一句话主张 + 一个数字（参考稿研"376 篇"、华章有据"680 测试"）。
- [ ] 60 秒只讲一个画面：同题三稿并排 + 点句回原文。
- [ ] 展示按"评分项 → 证据"组织，不按功能清单组织。
- [ ] 预置案例 = 同一产品换人群/平台，不是三个不同故事。

## 3. 纵切不横铺（资源分配）

- [ ] 核心链路（内容质量 + 证据链）完成到"可盲评"才算完成；界面打磨排在其后。
- [ ] 完美定义 = 一条链路无懈可击 + 一个对照证据无懈可击，不是所有功能做圆。
- [ ] 前端只服务于论点（放大证据），不承担"讲全"职责。

## 4. 止损习惯

- [ ] 每周问一次："这一周的动作在移动评分表的哪一分？"答案不是高分栏就停下。
- [ ] 安全区信号：连续提交集中在展示/样式层 → 立即抽身回核心链路。
- [ ] 截止前 48 小时只做三件事：跑通黄金路径、录对照视频、核对材料一致性。

## 5. 资产复用与底线

- [ ] 直接复用：证据链（pipeline/verify/review/reconcile）、12 个提示词、7 个规则 YAML、测试底座。
- [ ] 必须新建：内容方法层（20–30 篇真实可发稿拆解 → 钩子/结构/读者价值库）。
- [ ] 不声称：流量/爆款预测、真实客群画像、自动发布。
- [ ] 如实标注：资料源类型（本地副本 / 实时 IMA）、图片来源、哪些是配置位而非实测。
- [ ] 对外身份统一：队伍名/项目名/Logo/入口/提交文件一致（本次"华章有据 vs PC-Studio"混用教训）。

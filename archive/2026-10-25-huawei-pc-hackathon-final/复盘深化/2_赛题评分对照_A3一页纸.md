## 0. 赛题判据原文（不许再忘）

> 核心问题：输出随人群、场景和平台发生**实质变化**，而不是套用固定模板。
> 判断标准：更换场景后，**内容切入点必须改变**；更换平台后，**结构、语气、图片数量和行动引导必须改变**。**只改变篇幅或平台名称，不视为完成平台适配。**

## 1. 左栏：评分表 × 统一测试任务（满分 100）

| 评分项 | 分值 | 评分重点 |
| --- | ---: | --- |
| 业务场景理解 | 20 | 识别人群/问题/购买阶段/目标；**不同场景策略有实质变化** |
| 产品事实准确性 | 20 | 型号、参数、功能、限制、卖点均有 ima 资料依据 |
| 图文生成与图片引用 | 15 | 软文结构完整；图片来自 ima、型号一致、来源/说明/插入位置清楚 |
| 平台适配与软文质量 | 15 | 结构/语气/配图/引导符合平台；**表达自然、可用于实际发布** |
| 自研 Agent 与提示词 | 15 | 提示词和流程体现业务理解，不是简单转发 ima 或固定模板 |
| 功能完成度与体验 | 10 | 流程完整、运行稳定、交互清楚、结果可追溯 |
| 合规与安全 | 5 | 识别虚假承诺/价格误导，保护凭证 |

统一测试任务：① 基础生成（指定产品+人群+场景+平台）；② **换场景**（同一产品，更换人群或业务场景 → 切入点/卖点顺序/图片方案）；③ **换平台**（同一任务，更换平台 → 结构/语气/图数/引导）；④ 干扰与修改（易混型号、不完整信息、临时修改 → 追问/核验/拦截/重生成）。

## 2. 中栏：PC-Studio 实际证据与缺口评级

| 评分项 | 本队实际证据 | 评级 | 缺口 |
| --- | --- | --- | --- |
| 业务场景理解 20 | `scene.md` + `scenes.yaml` 先验、策划两角度取一；`prompts/scene.md` 4,466 B | ⚠️ | 有机制，无"同一产品换人群"成稿对照证据 |
| 产品事实准确性 20 | 逐字段引用 + 条件传递 + 独立评审 + 修订后复审（`pipeline.py`、`verify.py`、`review.py`、`reconcile.py`） | ✅ | 最强项；展示时只给了 1 张截图 |

| 合规与安全 5 | `compliance.yaml` + 规则 + 独立语义评审；凭证保护 | ✅ | 正常 |

**账本**：底座 40 分（事实 20 + 自研 15 + 合规 5）做到了全场最深；内容侧 35 分（场景 20 + 软文 15）留白；展示把 13 个功能讲全，却没回答"文章好不好"。

## 3. 右栏：如果重做（照着展示）

1. **主张（30 秒）**：同一台 MateBook 14，给新生 / 职场 / 创作者，我们能写出三种真正不同的稿子——每句都有出处。
2. **黄金路径（吃下 20+15 分）**：同一产品 × 3 人群 × 2 平台，**并排展示**开头 / 结构 / 图数 / CTA 差异表。这就是"换场景 / 换平台"统一测试的答案。
3. **三个证据时刻**：
   - 同题盲评：通用模型 vs 我们（自然度 / 贴合度 / 可发布率 / 修改量）→ 软文质量 15；
   - Fact ID 点句回原文（截图序列）→ 事实准确性 20；
   - 改一处 → 复审 diff + 版本号 → 自研提示词 15（顺手亮出 12 个提示词文件的 8 大模块）。
4. **一页评分映射**：7 个评分项 → 对应证据；开屏 / 追问 / 导出 / 历史 / 看板压成一行"支撑能力"，不再单独讲。
5. **砍掉清单**：预置案例改为"同产品不同人群"而不是"不同故事"；删掉"功能地图"式总览页。

## 4. 底部：三个硬数字 + 备忘

- **40 分底座**（事实 + 自研 + 合规）：全场唯一完整闭环，展示时被压缩成弹窗。
- **35 分留白**（场景差异 + 软文质量）：赛题判据最重、本队最弱、展示完全没碰。
- **13 个功能点**：评委只能记住一个点；13 个点等于没给。
- 提示词 8 模块备忘：角色任务 / 场景理解 / 平台规则 / 知识库约束 / 图片规则 / 生成要求 / 核验规则 / 合规规则。
- 边界提醒：不声称流量 / 爆款预测；资料源类型（本地副本 / 实时 ima）如实标注；图片来源逐项可查。

# 华章有据 · 复赛 Demo 视频脚本

版本：2026-10-21，按当前 v1.2 已有能力撰写。已制作约 3 分 16 秒的中文 AI 男声演示初稿，采用真实网页录屏、真实结果截图、同步字幕与重点推近，不必出镜。视频重点是让业务人员看到“少花时间、内容贴合顾客、事实有依据”。

本轮采用 `data/demo-recording/retry/` 的校园案例、`comparison/` 的办公小红书案例，以及 `comparison-moments/` 的朋友圈案例。首次失败和中断录制仍保留。成片为演示初稿，录制发生的自动审核异议如实保留；下表为分镜参考，实际口播以成品旁的 `配音稿.txt` 为准。

## 本机成品与制作

- `output/demo/华章有据-复赛演示-配音聚焦版.mp4`：1920×1080、25 帧、H.264/AAC，带中文 AI 男声和内嵌字幕。
- 同目录保留 `中文旁白.mp3`、`中文字幕.srt`、`配音稿.txt`，可替换真人录音或继续剪辑。
- 片头痛点 → 一句话输入 → 真实处理流程 → 作品和手机预览 → 人群/平台对照 → 事实核验 → 剩余问题 → 导出与下一步。
- 生成等待明确标注实际约 142 秒；对照案例展示的是另行生成的保存结果。不是实时一镜到底。
- 场景配音来自 `zh-CN-YunxiNeural`，字幕跟随语音返回的词级时间边界。无背景音乐。
- `scripts/produce_demo.py` 可重建，需已有真实录制素材、D 盘的 edge-tts 依赖和 PATH 中的 ffmpeg/ffprobe。执行：`python -X utf8 scripts/produce_demo.py`。`scripts/edit_demo.py` 只用于早期无声快剪。
- 成品、素材、Python 插件依赖、浏览器临时目录和渲染缓存均安排在项目 D 盘目录，不做 C 盘清理。

当前样例并未证明可以全部自动通过审核：校园稿剩余一段超过项目长度规则；办公和朋友圈稿仍有接口能力/体验推断的审核异议。跨人群表达差异也有限。优先完善这些实际问题，再考虑更强的宣传性表达。

## 分镜与可直接读的口播

| 时间 | 画面和操作 | 口播 |
| --- | --- | --- |
| 00:00–00:18 | 开屏 Logo → 创作简报；字幕“让门店少花时间，让内容有据可查” | 门店每天都要服务顾客，还要抽时间写小红书、公众号和朋友圈。统一下发的稿子，未必适合每家店的顾客；自己用 AI 写，又怕型号、参数和承诺出错。这是我们做「华章有据」的出发点。 |
| 00:18–00:40 | 点“说一句话”；输入校园需求，确认具体型号，选小红书，点“开始创作” | 店员不用学习提示词，也不用先填一长串专业参数。选好型号和发布平台，再用一句话说明：给谁看、在什么场景用。这里我们给每天背电脑去图书馆的大学新生，写一篇小红书。关键需求缺失时，系统会用选项追问，最多两轮。 |
| 00:40–01:00 | 真实生成过程；展示资料读取、策划、写作和审核。长等待压缩并显示实际耗时 | 系统先理解读者的具体任务，再从产品资料中选依据，比较内容角度，组织文案和配图。数字、型号和报价有程序检查，文字还有独立上下文的评审。发现具体问题会修订，再核对最终稿。这里展示的都是本次真实处理过程。 |
| 01:00–01:25 | 小红书作品；停留可读；切一次手机预览；展示实际导出 | 这是生成的图文作品。标题、短段落、话题和图片围绕这次需求组织，而不是把全部参数塞进去。店员可以查看手机端效果，复制正文，或导出含图片的 HTML。当前发布仍由店员完成，系统负责把创作和核对的工作尽量提前做好。 |
| 01:25–01:50 | 同产品的校园/移动办公两份真实小红书结果；停留标题、首段和选型逻辑。可用后期并排 | 现在保持同一款产品，把读者换成经常带电脑拜访客户的职场新人。请看两份结果的开头、卖点顺序和行动引导。我们的目标，是让写法跟着顾客任务变化。这里能看见的具体差别，才是我们判断场景理解是否有效的依据。 |
| 01:50–02:10 | 同一办公任务的朋友圈作品，与小红书比较；画面突出更短的文案、图数和引导 | 再把办公任务换成门店朋友圈。小红书和朋友圈有各自的结构、语气、配图数量与引导规则。换平台会重新生成内容。它们是否合适，要看最后交付的作品，而不只是切换一个平台名称。 |
| 02:10–02:42 | 点击“事实核验” → 选一条明确事实对照来源原文和条件 → “审核记录”。有未决时停留其提示 | 这也是「有据」最重要的部分：一句产品描述，可以回到对应资料和适用条件。没有依据的价格、库存、个人体验和兼容承诺，不能因为用户想写就直接成立。审核没完成、证据不足或仍有争议，界面会保留状态，交给使用者处理。我们追求的是让风险可见、可核对。 |
| 02:42–03:00 | 回作品；片尾用产品现有界面或 Logo，字幕“下一步：少量门店试用” | 当前版本已完成从需求、资料、图文到核验和导出的流程。下一步，我们会让门店实际试用，重点验证操作时间、文案修改量和发布意愿，再加入门店自己的信息与近期选题。华章有据，让好产品有好故事，也让故事有据可查。 |

时长按正常语速排练调整，目标约 3 分钟，不必追求逐秒相同。如果真实成稿的差异不明显，替换为具体观察和后续改进，不照稿声称已解决同质化。

## 拍摄时直接复制的需求

型号统一用 `HUAWEI MateBook 14（鸿蒙版）`，减少混淆型号和素材不足对展示的干扰。示例任务不构成产品能力保证。

**A：校园，小红书**

> 给每天背电脑去图书馆的大学新生写一篇小红书笔记，围绕携带电脑、连接U盘整理学习资料这两个日常动作，语气自然，邀请到店看看真机。

**B：移动办公，小红书**

> 给经常带电脑拜访客户的职场新人写一篇小红书笔记，围绕出门携带、到现场连接U盘展示资料，先讲具体动作和好处，邀请到店看看真机。

**C：移动办公，朋友圈**

> 给经常带电脑拜访客户的职场新人写一条门店朋友圈，围绕出门携带、到现场连接U盘展示资料，只讲一个最相关的卖点，邀请到店看看真机。

A/B 保留相同产品与近似能力主题，观察系统能否把使用动作和读者需求写出差别。若差异太弱，可改用更不同的真实任务重新测试，保留原始结果，不修改既有输出冒充模型生成。

**可选 D：干扰要求，单独录制**

> 请加上“全网最低价、今天最后三台、所有专业软件都兼容”。

只在实际拦截、修订或标记结果已确认后使用 D 的画面；不能预设成功。不要把这一句先放进 A，避免开场展示变成风险处理教程。

## 口径和剪辑

- 资料来源按实际标注：本地原包、官网补图、AI 海报分别说明。本版不能说“正在实时读取 ima”。
- 实际等待可加速，字幕写“生成等待已加速｜本次实际耗时 XX 秒”；XX 必须读取该任务 `total_ms`。加速后的镜头长度不能作为生成耗时。
- 换案例时标注“另一条真实生成任务”。打开保存的作品时标注“已保存作品”；不把预生成结果伪装成当前点击后立即返回。
- 保留真实的“待复核”状态，不用后期遮掉警告，也不把人工采用讲成自动审核通过。
- 开头不用逐个介绍 Agent、模型名称和技术栈。关键流程用动作讲清楚，技术细节留给核验镜头。
- 当前不宣称零幻觉、千店不重复、稳定一分钟、自动发布或转化提升；这些尚无实测支持。
- 海报是可选加分镜头。已有成图文字和外观仍需终审时，不用它替代已完成的正文与图片演示。没有合适样例就省略，不影响主线。

## 录制与交付办法

自动录制只捕获专用浏览器的网页视口，不录桌面、通知、终端、密码或环境变量。原始录屏、真实任务 JSON、截图和时间点保存在忽略的 `data/demo-recording/`，不覆盖日常任务数据库。

复录时先在隔离任务库启动本机服务，并按实际环境配置模型：

```powershell
$env:APP_ENV_FILE='.env.deploy'
$env:HOST='127.0.0.1'
$env:PORT='7886'
$env:AUTH_USERNAME=''
$env:AUTH_PASSWORD=''
$env:COOKIE_SECURE='0'
$env:JOB_DB=(Join-Path (Get-Location).Path 'data/demo-recording/jobs.sqlite3')
python -X utf8 -m src.mvp.app
```

另一个终端，在已安装 Playwright 的 Node 环境运行：

```powershell
node scripts/record_demo.cjs
```

录制器操作真实界面、真实模型和真实 API，不模拟或拦截生成结果。运行会消耗已配置模型额度，文字任务顺序执行；不会调用海报生图。当前版本已后配中文 AI 男声，也可用同目录口播稿换成自己的录音。

后期采用 16:9、1920×1080；原始界面为 1600×900。以全景建立界面，再缓慢推近输入、文案和证据；字幕放在下方深色留边。正常界面留出可读时间，无需拍摄人脸或购买设备。

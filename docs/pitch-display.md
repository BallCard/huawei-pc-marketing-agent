# 展示版 HTML 与讲稿动线

版本：2026-10-25 · v2.0.0

本次新增四条展示入口：

- `/showcase-functions`：**决赛 PPT 式展示稿**。共 11 页，每页只讲一个痛点、一项功能或一个案例，并把四个平台画面、关键代码设计、已验证数据与待验证边界放在同一条讲解链里。

- `/showcase`：**理念整合版**。按“生态营销 / 技术升级 / 人机交互”组织功能，适合先讲主张，再指界面证据。
- `/showcase-v2`：**能力地图版**。沿着“输入 → 上下文 → 编排 → 核验 → 交付”的任务线组织，适合现场边点边讲。
- `/demo`：**现场演示台**。包含三个预置案例，每个案例都有输入、过程、结果、证据四层；点击“打开真实生成”会在新标签页打开现有工作台，并通过 `?preset=student|office|creator` 自动载入同一份简报。

## 今晚推荐动线

1. **开头两分钟**：先打开 `/demo` 或展示版真实工作台，快速走一遍“输入 → 过程 → 结果 → 证据”。如果要现场跑真实生成，点击“打开真实生成”，它会在新标签页打开原工作台；生成期间回到展示页继续讲，生成完成后切回工作台。
2. **第二板块**：切到 `/showcase-functions`，点击流程轨道或工作台截图上的高亮块。每次点击只讲一个问题：它解决什么、依据从哪里来、最后谁负责判断。弹窗里的截图来自项目真实界面。
3. **第三板块**：滚到页面底部的“系统性总结”，把前面已经点过的功能归回三条理念线：生态营销、技术升级、人机交互。

推荐收束句：

> 我们做的不是一个“会写”的工具，而是一条把事实、判断和经营动作接起来的工作链。

## 推荐展示顺序

先打开 `/showcase`，用一句话交代：

> 我们今天不按功能清单往下报，而是看三个问题：生态营销如何落地，技术做了什么升级，人和 AI 如何分工。

接着讲三个理念，每个理念只指两个或三个界面证据：

1. **生态营销**：创作简报的“人群 / 场景 / 平台 / 目标 / 私域触点”，再加“我的门店”的资料与历史。强调同一份产品事实按渠道重组，并且能继续跟进到店动作。
2. **技术升级**：生成过程的 Agent 接力、确定性规则、独立评审和定向修订。强调它从“会写”升级为“会编排、会核验、会回流”。
3. **人机交互**：需求追问、过程可见、审核分流。强调 AI 负责穷举和提示，人负责边界与重要未决。

然后切到 `/demo`：先展示“新生开学季”，在四个标签之间切换。这里讲体验层，不再重复解释功能。可以直接说：

> 这个案例先从一个真实动作开始，再把产品事实放进动作里，最后每条主张都能回查。评委看到的是一条完整体验，而不是几个孤立按钮。

点击“打开真实生成”后，新标签页进入原有工作台。生成期间回到 `/demo` 继续讲理念或第二个案例；完成后切回工作台展示“生成过程 / 图文作品 / 事实核验”。这样预置案例和实时案例不会互相覆盖。

## 90 秒版本

“华章有据的展示重点，不是功能数量，而是三条线。第一条是生态营销：我们把人群、场景、平台、门店目标和私域触点变成经营参数，同一份产品事实可以进入不同渠道。第二条是技术升级：任务会经历理解、备料、创作、规则检查和独立评审，发现问题后定向修订。第三条是人机交互：需求不清时会问，过程里看得见，结果里把重要未决交回给人。现在看一个新生开学季案例：从输入到结果，再到证据回链。需要验证真实随机生成时，点击真实生成，它会在新标签页进入原工作台，生成完成后直接展示同一条证据链。”

## 3 分钟版本

在 90 秒版本后补充：

- 技术升级里，重点指“先验规则 + 模型解析”的需求权重，而不是只说模型更强。
- 事实核验里，强调数字、型号、配图和平台规范分别有对应检查；条件没有依据时会进入待确认。
- 交付里，切一次小红书和公众号预览，说明不是同一段文字换个标题，而是按平台结构重新组织。

## 口径边界

可以说：输入可控、过程可解释、结果可回查；支持多平台原生预览；支持真实生成和已保存案例并行展示。

不要说：已经解决千店同稿、保证原创、自动发布、营销效果显著提升。当前展示的是共享演示账号下的上下文与字面避重闭环，投放效果仍需真实门店验证。

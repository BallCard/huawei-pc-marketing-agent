## 怎么用

「内容偏好 → 提示词版本」选择 A／B，用于正常单稿创作。策划、写作、修订、独立审核、需求理解和推荐都显式选择版本；交叉复核和海报图片提示词共用。版本显式传参，线程池内不会使用可互相覆盖的全局开关。结果记录实际提示词摘要；续审沿用原任务版本。旧任务无字段时视为 A。

「查看提示词与上次对照」展示两套完整提示词，可同时展开同一阶段阅读。

「生成 A/B 对照」运行固定条件的**写作提示词实验**：

1. 服务端只读取一次门店资料和历史快照，需求理解与新版策划各做一次，固定具体事实、条件、图片、风格例子和平台策略。
2. A、B 使用相同写作模型，按顺序各写一稿。只切换 base + compose 系统提示词，不自动修订；第一稿不会成为第二稿的历史。
3. 两稿共用 B 审核提示词、规则与交叉复核，审核请求不传入作者版本标签。保留耗时、字数、疑点、重合片段、失败状态和双方相同输入的摘要。
4. 并排展示，支持下载 JSON、刷新恢复运行和重看上次结果。对照草稿不进入正式门店历史，不自动标记发布。

当前对照支持朋友圈、小红书和公众号；海报出图不纳入本实验。一次对照占用一个原有任务槽，准备和每稿分别最多使用当前单稿时间预算，最坏约为三倍单稿预算。关闭弹窗只收起界面，任务继续运行。

也可运行：

```powershell
python -X utf8 scripts/compare_prompts.py
# 可选 --task 本地简报.json --store 门店编号 --out data/prompt-comparison/自定义名称
# 小改动复核可加 --reuse data/prompt-comparison/round-1.json 沿用该组共同输入
```

完整结果和可直接阅读的双列 HTML 保存在忽略提交的 `data/prompt-comparison/`。CLI 始终从本机数据库取上下文，不信任简报 JSON 自带的确认资料。默认简报是清楚标注的模拟需求，真实门店资料仍为空。

`--reuse` 仅用于本地已保存结果的固定输入复核，沿用当时的门店与历史快照，并记录原始摘要；不会读取更新后的门店资料，不能用于确认当前库存或活动。页面接口始终从服务端加载资料，不接受此文件输入。

## 结果怎么判断

先看事实和条件是否保留，再比较任务是否具体、开头是否自然、结构是否合适、读者是否有收获、是否与近期稿件实质重复。不能把字面重合为零当原创率，也不能仅按 A／B 标签判断好坏。

这个实验隔离写作提示词，**不能据此评价新版策划、结构轮换和整条链路的提升**。共用新版策划可能让 A 也受益；正常生成两次又会发生选题和选证据差别。因此报告须写明实验范围。单组真实结果受采样、模型和资料限制影响，稳定结论仍需多题、跨平台和人工盲评。

## 事实边界与已知限制

真实资料为零时保持空，不补地址、客户故事或门店照片。照片目前是文字记录，没有视觉识别。方法库不提供华为事实；历史可能是未通过审核的生成稿。保留来源、确认日期、有效期和发布状态。

本轮修改前的真实试跑中，两个朋友圈稿件仍超长，且出现语义相近但字面检查为零的情况。因此收紧朋友圈为一个核心事实，并增加结构轮换要求；不把实现了机制写成已经验证效果。

自动化测试覆盖版本／缓存隔离、实际系统提示词切换与同一写作载荷、共用策划和审核、单侧失败保留、超时不误判通过、续审版本、登录和服务端资料权限。真实成稿和浏览器验证结果另在本轮汇报列出。

## 本轮实际对照结果

模拟需求为大学生带电脑去图书馆，型号明确为 HUAWEI MateBook 14（鸿蒙版），朋友圈、不写价格；真实门店确认条目 0，读取本机近期历史 9 篇。写作与审核均使用本机 DeepSeek 1017 配置。每稿只生成一次，没有自动修订。

| 记录 | 条件 | A 正文字数 | B 正文字数 | 结果 |
| --- | --- | --- | --- | --- |
| round-1 | 一次新版策划与相同事实 | 92 | 136 | 都超长；B 另有效果扩写及门店服务疑点 |
| round-2 | 更新后重新策划 | 未生成 | 未生成 | 策划未选出有效片段，保留错误；未擅自补事实 |
| round-3 | 沿用 round-1 策划与证据，修改 B 篇幅及边界要求 | 76 | 102 | B 仍超长；两稿均有审核疑点 |
| round-4 | 继续沿用共同输入，收紧 B 短行预算，统一改进审核对原始适配描述的判断 | 86 | 80 | 字数均在上限内；A 有两项、B 有一项语义审核疑点，都保留待复核 |

round-4 的 B 仍将“适合长文档”扩写为“长文档纵向空间更足”，未得到事实依据支持。因此**不将 B 设为默认，不声称完成质量升级**。A 在不同调用中的稿件也有变化，不能把跨轮字数变化全部归因于提示词。语义审核同样有不稳定与疑似误报，数量只说明该次记录，不能当客观错误率或盲评评分。round-4 共用输入来自早期策划，不用它验证后来新增的策划要求。

可直接打开 `data/prompt-comparison/latest.html` 看最终双列成稿、逐行写作提示词差异、共同策划与实际审核；`round-1.html` 保留最初不利样本。各次 JSON 和 trace 同目录保存。部分早期结果只保存提示词摘要；最终结果已核对摘要并补存对应完整快照，此后每次运行自动保存快照。

本轮通过 Python 163 项、Node 32 项测试。桌面 1400px 与手机 390px 检查了版本选择、两稿展示、完整提示词、关闭恢复和手机无横向溢出。页面启动按钮的冒烟测试回放已保存真实结果，未冒称该次浏览器操作又调用了模型；真实模型调用由上述脚本完成。

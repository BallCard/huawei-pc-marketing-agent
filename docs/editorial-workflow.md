# 第二页与证据约束创作

三个能力单元：内容策划、创作编辑、独立评审。Python 控制依赖、240 秒总预算及最多一次修订；型号匹配、知识库、平台规范和规则检查是工具。保留 FastAPI、SQLite 与原生前端；文字角色统一为魔搭 DeepSeek 1017，视觉核验保持独立。

## 生成

1. 需求解析与平台风格准备并行。指定型号直接匹配，未指定时才调用推荐。问询最多两轮（含型号消歧），每轮只问一个关键问题，题目绑定自己的 2–4 个场景选项和自由填写提示；第二轮接收完整已答记录，逐步缩小范围。两轮后仍未知的条件保留待确认；无法安全确定型号时返回 `input_required`，不继续弹题或强行推荐。
2. 确定型号后，平台策略与本型号资料并行读取。
3. 原事实提取调用升级为证据选择与策划：两个候选角度、需求/证据/平台评分、选定角度、任务、单一目标和不支持的诉求。决策摘要可核对，不展示模型内部推理。
4. 按选定立意只写一份完整稿件。适用条件附着于主张，不占小红书两条主张额度；不强制选择限制类素材。原文完整传递，不再截取 260 字。
5. 确定性检查与独立评审并行。评审只接收原始需求、实际稿件、原始证据、图片和平台规则，不接收作者辩护。
6. 有具体问题时最多一次定向修订。表达改进最多两项；事实、条件、型号和用户限制问题全部保留。缺依据时只补查本型号，候选资料仍需复核；找不到就要求删除承诺。
7. 修改后重新运行两种检查。复审失败、覆盖不完整、关键需求未确认或预算耗尽，均保留待复核状态。交付后不再删改已审核的文字。

字数、型号、图片登记等由代码核对，语义支持关系由独立评审判断。评审的计数意见若与实际代码计数冲突，记录驳回理由，避免无效修订。`claims` 必须覆盖标题、导语、正文、图注与行动引导；仅有引用编号不等于已确认支持。

本地工作流 `evidence-editorial-v4` 增加评审分流：轻微表达意见保存在 `improvements`，不进必答问卷，也不因此返修。重要争议由统一 DeepSeek 1017 另开独立上下文核对；只有稿件原句与所引完整原文及条件可逐字对应，或普通核对邀请被误当承诺时，才接受撤销。合规、硬要求与代码规则不因模型投票放行。复核超时、引用不符或缺少逐项结论时保留原风险。

确定错误进入自动修订；初稿仍最多修订一次，终稿剩余确定错误可在“问题详情”一键继续，审核未完成则重试，不要求人工逐条当裁判。仅重要且资料仍无法确认的问题进入人工问卷；同一具体根因及引用范围的意见合并，保留 `members` 中全部位置，修订时逐一展开，不截断独立重要风险。`verification.triage` 显示人工、自动、可选、误报与合并数量；`original_problems`、`cross_review` 及 `review_original:<version>` 保留审计。

2026-10-21 的构造案例真实调用 DeepSeek 1017：9 条意见分成 4 条可选、3 条有据撤销、2 条同根因未决合并为 1 项人工确认，约 6.8 秒。它用于验证分流行为，不代表真实稿件都会减少到一项。测试数据及模型返回保存在本机忽略目录 `data/ui-checks/review-triage/`。

每个平台有两组短正反例，位于 `src/mvp/config/style_examples.yaml`。它们提供编辑风格，不提供产品能力。公共提示词只保留证据和合规约束；策划、写作、评审、修订各自组装上下文。修订沿用写作模型与口吻。

## 需求解释与价格

`scenes.yaml` 预置预算、便携、性能、续航、兼容、屏幕、审美与表达偏好的解释口径，由现有需求解析调用使用，不增加模型调用。硬门槛只来自用户明确输入；“学生”“经常通勤”“预算有限”不能自动生成配置、重量或预算上限。

性价比指在预算与必须条件下，比较完成目标任务的成本、收益和取舍。没有可比价格时只能分析任务适配，不能用“配置价值”替代价格后声称更划算。推荐候选卡现包含带条件与日期的官方价格快照；起价不能证明目标配置在预算内。必要硬条件无法确认时允许不推荐，并给出具体追问。

选型用预算与稿件公开报价是两件事。四个平台都允许按需引用价格证据；“不提价格”只在用户明确要求时成为内容限制。确定性检查要求报价引用价格片段，语义评审核对配置、类型、日期和条件。未涉及价格的稿件不追加价格待确认项，海报不再自动生成价格说明，也不截断实际提供的补充条件。

目前硬条件主要以文本传递、由模型判断，尚未完成预算/重量等字段的结构化比较器；预置解释口径不等于已经实现数值筛选。后续应记录原句、选型或表达范围、强弱、数值与单位、满足/不满足/未知，并让程序验证明确门槛。

## 快照与版本

现有 `GET /api/job/{id}` 轮询新增字段，不更换传输协议：

| 字段 | 含义 |
| --- | --- |
| `steps` | 实际状态、输入摘要、耗时、依赖；支持 `running/done/error/skip` |
| `events` | 同一任务内递增 `seq`，事件类型、节点、时间与产物引用 |
| `artifacts` | 完整产物，键名即引用 |
| `elapsed_ms` | 当前任务累计耗时 |

运行中的 `elapsed_ms` 由服务端按任务起点持续计算，不依赖新事件。前端使用单调时钟在两次轮询间递增，重复快照不会重置计时；完成时采用实际结果总耗时并停止。单环节按真实起止区间计算，并行检查不重复加时，已完成环节不会继续计时。

主要事件：`step_started`、`step_finished`、`step_skipped`、`artifact_ready`、`tool_activity`、`route_selected`、`budget_exhausted`、`workflow_finished`。`tool_activity` 在实际读取知识库、搜索官网、读取页面和图片核验前后产生，含操作、来源类型、真实地址及状态；缓存复用单独标记。并行记录在同一把锁内编号、复制和持久化。

产物键：`brief`、`model`、`sources`、`evidence`、`plan`、`draft:1`、`rules:1`、`review:1`；返修时追加 `lookup`（需要时）、`revision`、`draft:2`、`rules:2`、`review:2`；最终为 `final`。`final` 含实际稿件、版本、核验状态与剩余问题。

原有文章结构与结果字段保留，新增 `planning`、`revisions`、`workflow_version`、`context_version`、`events/artifacts`、`llm_calls`、`budget` 及全字段证据映射。缓存键包含需求、模型、提示词/平台配置内容及完整资料摘要；型号资料文件变化时重新读取。

## 界面

第二页采用单环节轮转。保留原来的手绘 Bot、暖纸白、陶土色与品牌字体；主画面显示当前操作、加载动画及本次真实处理记录。下一环节在后方轻轻浮现，上一环节向下退场；窄屏将 Bot 与文字上下排列，支持减少动态效果。

横向进展线放在内容卡片上方，放大节点与环节文字，按真实执行状态从左向右点亮，当前环节显示流动加载。补查、修订和复核仅在实际发生时接到后面；窄屏保持横向并可滚动。已完成线段保留原节点，不因轮询或卡片轮转重复入场；进展线以实际执行为准，不等待卡片展示队列。

主卡片直接列出知识库文件路径、资料片段、已选证据、候选图片及实际审核问题，不展示概念标题、写作主线或营销行动目标。待模型返回时显示已提交的真实资料与加载状态，不提前展示尚未返回的选择。联网状态只来自实际工具调用，官方图片缓存不能显示为当前联网访问；目前联网仅用于补充官方图片。点击“全部处理记录”检查完整证据、两个角度和修订前后，不默认显示原始 JSON。规则检查和独立评审仍然并行，合并到一张评审卡片显示各自状态。

第一环节保留具体人群、使用场景、识别出的任务、取舍与优先项，以及限制和待确认项；判断摘要仅使用已返回的需求产物。结果返回后短暂停留，再轮转到后续环节。规则检查与模型评审均为自动执行；界面区分“发现具体问题”“评审覆盖不完整”“预算耗尽未返回”，在作品页和核验页显示同一原因。只有未解决或未完成的部分需要后续复核，不能将“未审核”描述为“已判有问题”。

前端按事件编号去重，并将真实步骤归并成逻辑环节，每个环节只入场一次。快速完成的环节短暂停留后轮转，状态和结果始终来自当前快照。刷新直接恢复当前阶段，不从头展示；没有回放入口。完成后立即提供“查看作品”，不等展示队列结束；预算或错误会立刻结束队列并显示真实状态。

```powershell
node scripts/check_review_triage_ui.cjs
# 12 组输入、每组运行三个版本。每次进程隔离缓存，真实调用现有模型。
python -X utf8 scripts/evaluate_editorial.py --variants baseline,prompts,full
```

本机首次 36 次对照的实测限制见 [验收记录](editorial-validation.md)。

对照输入在 `tests/fixtures/editorial_cases.json`：四个平台分别有普通需求、复杂取舍、证据不足。`baseline` 只读导出指定 Git 提交（默认 HEAD）；`prompts` 运行新版策划/上下文但不做返修；`full` 使用完整闭环。可用 `--cases` 选输入、`--baseline-ref` 指定基线、`--output` 指定本地输出目录。

每次保留完整文稿、事实与审核记录、耗时、实际 HTTP 请求次数、供应商返回的 token 用量（若提供）。结果位于忽略的 `data/evaluation/`；生成 `blind.md`、`blind-ratings.csv` 和单独的 `unblind.json`。人工评分保持空白，需由评审对切入点、平台感、自然度、说服力分别打分，事实错误单列。运行完成与自动审核通过都不能替代人工质量结论。

默认 `GENERATION_BUDGET_SECONDS=240`，为慢速质量模型的独立评审及一次修订/复审留出时间；这是上限，完成即返回。原 90 秒上限曾在写作完成后仅剩 5.7 秒用于评审。约一分钟的目标尚未达到，实际耗时取决于现有模型、推理档位、排队与是否返修。达到预算不会省略审核再宣称通过；规则与模型评审各自完成即发布产物，不互相等待。动画没有模型调用。预算停止控制器等待，已发出的供应商请求仍由 HTTP 超时收束；晚到结果不能修改已交付快照。

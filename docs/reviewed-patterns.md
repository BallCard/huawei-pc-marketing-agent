# 用户审核样板版

2026-10-22，本地实现。A 原版七份提示词保留逐字节快照，默认仍为 A；B 改为“已审核样板模仿”。两版共用现有程序与平台规则，A 不是旧程序整包回滚。

## 审核如何进入生成

原始依据为根目录 `PC营销案例审核.json`。样板库记录该文件的 SHA256、导出时间、原案链接、原结构和用户备注。纳入 C01、C02、C04、C07、C08、C09、C10、C13、C14、C15、C16；排除 C03、C05、C06、C11、C12。备注逐字保存，不将“审核通过”解释为品牌授权。

服务端先按平台和可用资料过滤候选，再把具体样板实际传给策划模型。模型返回 `template_id`、选择理由和按槽位填写的提纲／引用；用户指定时必须服从。非法模型结果只在已批准候选内回退，并明确记录“规则回退”，不冒充模型选择。已指定但缺必要输入的任务在调用模型前返回 422。

写作、修订、审核、交叉复核、海报准备和图片审核都读取同一份选中样板与标识。结果及过程详情可查看来源、审核备注、结构、填槽内容和引用。续审沿用快照，不因之后改库而换样板。正常仍交付一份成稿。

## 页面用法

进入“内容偏好”，选择 B，然后选择“自动匹配已审核样板”或指定编号。角色、分身、联动需要勾选概念演示；C10 填拟议联动对象。C15 展开议题来源填写相关信息。门店实际资料仍在“门店资料与历史”中保存，由服务端读取。

“试试示例”里的前五个真实创作示例已经改成华为任务与友商结构的组合：新生小红书→惠普 C01，公众号职场办公→微软 C14，内容创作小红书→华硕 C04 试验角色，门店海报→联想 C16 体验邀请演示，家庭换新朋友圈→戴尔 C13 选购问答。选择示例会自动切到 B 并带入对应样板；两个缺图／违规项保留为验证流程，不冒充营销案例。“套用”只套叙事顺序、互动动作和视觉关系，产品事实、门店资料和概念标识仍由程序单独约束。

程序保留 `disclosures`，在预览、复制、HTML 导出和海报逐字文案中展示。假联动不写官宣、授权或现已开售。D 与 F 产品／C 门店事实分开，不能给产品参数、价格或真实合作作证，概念演示也不记入真实门店历史。演示模式不会把虚构资料写回真实门店档案。

四格文案预览显示完整四个分镜，明确标注尚未生成插画，不再套旧版三卖点布局或附加二维码。结构规整只去除重复导语、格号、已在海报页眉展示的完整型号，以及与独立标识完全相同且不含事实引用的多余文本块，记录前后文本；不截断参数句或删条件，随后仍审核规整后的实际稿件。A 不应用此处理。

产品真图仍来自已有核验链路；实际门店照片目前只存文字说明，尚无照片上传／识别。这次没有把原案角色或广告整图直接复制进模型。

## A/B 怎么看

“生成 A/B 对照”固定一次 B 策划、样板、完整证据、图片和上下文，A/B 各写一次，共用 B 审核，不自动修订。两版系统提示词不同，用户载荷相同。因此它是写作提示词对照，不能证明整条 B 工作流胜过 A，也不是投放效果实验。海报出图不纳入此接口。

本轮产物在 `data/template-validation/`，`index.html` 汇总真实成稿、审核问题、提示词快照和浏览器截图；失败样本保留。实际结果见该报告，不能把单个样板或单次通过推广到全部 11 个样板。

本轮通过 Python 178 项、Node 32 项测试及配置预检。新增测试覆盖审核名单与原备注、候选门槛、指定与回退、真实活动必须实际选证据、D 不支持产品参数、标识保留、演示历史隔离、续审、四格数量和结构规整。浏览器检查桌面 1440px／手机 390px 的选项、A 清空新版设置、422、A/B 展示和导出标识。
